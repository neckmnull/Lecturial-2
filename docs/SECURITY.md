# Безопасность Lecturial 2

Документ для специалистов по информационной безопасности: какие данные обрабатывает
приложение, куда они уходят, как защищены и какие риски остаются. Описана версия 1.13.6.
Все утверждения проверены по исходному коду; ссылки ведут на файлы, где это видно.

## Кратко

- Своего сервера нет. Приложение обращается только к сайтам университета, GitHub
  и, если пользователь сам подключил Outlook, к Microsoft.
- Аналитики, рекламы и SDK для отчётов о сбоях нет.
- Сессия личного кабинета (ЛКС), загруженные из него оценки и токены Microsoft
  зашифрованы AES-256-GCM ключами из Android Keystore.
- Пароль от ЛКС приложение не получает: вход идёт на странице университета в WebView,
  ограниченном доменом университета. После входа WebView ничего не хранит.
- Резервное копирование и перенос данных на другое устройство полностью запрещены.
- Только HTTPS и только системные центры сертификации, это задано в
  `network_security_config.xml`.
- Обновление устанавливается, только если APK подписан тем же ключом, что и установленное
  приложение. Это проверяется до открытия системного установщика.
- Ссылка на онлайн-занятие приходит с сайта расписания. Принимаются только адреса `https`,
  ссылки других схем (`intent:`, `file:`, `javascript:`) отбрасываются.
- Остаточные риски перечислены в разделе [«Остаточные риски»](#остаточные-риски).

## Какие данные обрабатываются

### Учётные данные и сессии

| Данные | Где хранятся | Защита |
| --- | --- | --- |
| Cookie сессии ЛКС | SharedPreferences `lks` | AES-256-GCM, ключ Keystore `lecturial_lks_session` ([`SecretBox.kt`](../app/src/main/java/com/rassvet/lecturial/data/local/SecretBox.kt)) |
| Cookie, кеш и DOM storage WebView | Нигде | Стираются сразу после входа: остаётся только зашифрованная копия cookie |
| Токены Microsoft (access и refresh) | SharedPreferences `outlook_auth` | AES-256-GCM, ключ Keystore `lecturial_outlook_tokens` ([`MicrosoftAuth.kt`](../app/src/main/java/com/rassvet/lecturial/data/outlook/MicrosoftAuth.kt), `TokenVault`) |
| PKCE verifier и `state` для входа в Microsoft | SharedPreferences Outlook | Открытым текстом, только на время входа, затем удаляются |
| Пароль ЛКС | Не хранится и не передаётся приложению | Вводится на странице lks.siriusuniversity.ru |

Ключи Keystore неэкспортируемые и создаются без требования аутентификации пользователя,
иначе не работало бы фоновое обновление. Они защищают от копирования файлов приложения
на другое устройство, но не от кода, который выполняется от имени приложения
(например, на устройстве с root).

### Учебные данные

| Данные | Где хранятся | Защита |
| --- | --- | --- |
| Снимок ЛКС: оценки, посещаемость, домашние задания, сессия, уведомления и новости | `files/lks/snapshot.json` | AES-256-GCM тем же ключом, что и сессия. Файл старых версий шифруется при первом запуске |
| Выбранная группа, настройки, сокращения предметов, оформление | DataStore `UserPreferences` | Песочница приложения |
| Кеш расписания по неделям, планы, задачи, дедлайны | Room `lecturial.db` | Песочница приложения |
| Отметки плана дня (что сделано) | SharedPreferences `day_planner` | Песочница приложения |
| Учётная запись Outlook (адрес или имя), связь пар с событиями | SharedPreferences и JSON в `files/` | Песочница приложения |
| Связь пар с событиями Google Календаря | SharedPreferences `device_calendar_sync` и JSON | Песочница приложения |
| Скачанный APK обновления | `cache/updates/` | Песочница. Установщику выдаётся через `FileProvider` только на чтение |

Расписание публично, а планы пользователь вводит сам, поэтому эти данные защищены
песочницей Android без дополнительного шифрования.

### Резервные копии

`android:allowBackup="false"`, а [`data_extraction_rules.xml`](../app/src/main/res/xml/data_extraction_rules.xml)
исключает все домены и из облачной копии, и из переноса на новое устройство. Ни одна
из перечисленных выше записей не попадает в Google-бэкап или adb backup.

## Сетевое взаимодействие

| Адрес | Зачем | Что передаётся |
| --- | --- | --- |
| `schedule.siriusuniversity.ru` | Расписание (Laravel Livewire) | Название группы или преподавателя, служебные cookie и CSRF-токен публичного сайта |
| `lks.siriusuniversity.ru` | Вход в ЛКС, оценки, посещаемость, домашка | Cookie сессии ЛКС. Запросы раз в 3 часа в фоне и при открытии приложения, если данные устарели |
| `api.github.com` | Проверка новой версии | Без данных пользователя |
| `github.com` и CDN GitHub (через redirect) | Скачивание APK обновления | Без данных пользователя |
| `login.microsoftonline.com` | Вход в Outlook (OAuth 2.0, PKCE) | Код авторизации, PKCE verifier |
| `graph.microsoft.com` | Создание и изменение событий в календаре Outlook | Пары и планы: название, время, аудитория, преподаватель |
| `t.me` | Ссылка на Telegram-канал | Открывается во внешнем браузере, приложение само не обращается |

Google Календарь приложение не трогает по сети: события пишутся в выбранный
календарь через системный `CalendarContract`, дальше их синхронизирует аккаунт Google
на устройстве.

**TLS.** [`network_security_config.xml`](../app/src/main/res/xml/network_security_config.xml):
cleartext запрещён, доверие только системным центрам сертификации. Сертификаты,
добавленные пользователем или профилем устройства, release-сборка не принимает,
debug-сборка принимает для отладки через прокси. Certificate pinning нет, причина
в [остаточных рисках](#остаточные-риски).

**Cookie ЛКС в OkHttp.** Своя `CookieJar` выдаёт cookie только для
`lks.siriusuniversity.ru` и только по HTTPS (`secure()`), поэтому при redirect на
другой хост они не уходят ([`LksClient.kt`](../app/src/main/java/com/rassvet/lecturial/data/lks/LksClient.kt)).

## Аутентификация

### Личный кабинет (ЛКС)

1. Экран входа открывает `https://lks.siriusuniversity.ru/login` во встроенном WebView
   ([`LksLoginScreen.kt`](../app/src/main/java/com/rassvet/lecturial/ui/LksLoginScreen.kt)).
2. Пароль вводится на странице университета. Приложение не читает поля формы. На странице
   входа оно выполняет один скрипт, который ставит галочку «Запомнить меня», чтобы
   сессия жила недели, а не часы.
3. Когда загрузилась страница ЛКС (хост сравнивается точно), отличная от входа, приложение
   берёт cookie для `https://lks.siriusuniversity.ru` из `CookieManager`, шифрует
   и сохраняет их.
4. Сразу после этого из WebView удаляются cookie, DOM storage, HTTP-кеш и история.
5. Дальше данные загружаются через OkHttp с зашифрованной копией cookie и разбираются
   jsoup. Если сессия истекла, пользователь видит предложение войти заново.

Защита экрана входа:

- переходы в главном фрейме разрешены только по HTTPS на `siriusuniversity.ru`
  и его поддомены. Остальные ссылки открываются во внешнем браузере, другие схемы
  игнорируются;
- доступ к файлам и content-провайдерам выключен, `addJavascriptInterface`
  не используется;
- `filterTouchesWhenObscured`: нажатия через оверлей другого приложения не проходят;
- `FLAG_SECURE`: экран входа не попадает в скриншоты, запись экрана и превью
  недавних приложений;
- ошибки TLS не переопределяются, страница с плохим сертификатом не откроется.

JavaScript и DOM storage включены, потому что без них не работает страница входа
и капча.

Выход («Выйти» во вкладке «Учёба») стирает зашифрованные cookie, снимок ЛКС, данные
WebView и отменяет фоновое обновление.

### Outlook (Microsoft Entra ID)

- Публичный клиент OAuth 2.0 с PKCE (S256) и проверкой `state`
  ([`OutlookSync.kt`](../app/src/main/java/com/rassvet/lecturial/data/outlook/OutlookSync.kt)).
- Вход открывается в Custom Tab системного браузера, не в WebView приложения.
- Разрешения: `offline_access User.Read Calendars.ReadWrite`.
- Redirect URI: `com.rassvet.lecturial2://oauth`, его принимает `OutlookAuthActivity`.
  Перехват этой схемы другим приложением бесполезен без PKCE verifier, а подделанный
  ответ отбрасывается проверкой `state`.
- Client ID задаётся при сборке (`lecturial.msClientId`) и секретом не является.
  Без него синхронизация с Outlook скрыта.
- «Выйти» стирает токены, учётную запись и записи о синхронизированных событиях
  на устройстве.

### Google Календарь

Входа нет, используется системное разрешение на календарь. Приложение пишет только
в календарь, который выбрал пользователь, и помечает свои события
(`CUSTOM_APP_PACKAGE`, `CUSTOM_APP_URI`, метка в описании). Удаляет оно только
события со своей меткой. При отключении все свои события удаляются.

## Уведомления

Уведомления ЛКС (новые оценки и сообщения кабинета) помечены `VISIBILITY_PRIVATE`
и имеют публичную версию без содержимого: на заблокированном экране видно только
«Личный кабинет — Есть новые данные».

## Разрешения

| Разрешение | Для чего |
| --- | --- |
| `INTERNET` | Расписание, ЛКС, обновления, Outlook |
| `READ_CALENDAR`, `WRITE_CALENDAR` | Синхронизация с Google Календарём (запрашиваются при включении) |
| `POST_NOTIFICATIONS`, `POST_PROMOTED_NOTIFICATIONS` | Напоминания, текущая пара, новые оценки, дедлайны, обновления |
| `SCHEDULE_EXACT_ALARM` | Напоминания точно ко времени пары |
| `RECEIVE_BOOT_COMPLETED` | Восстановить напоминания и фоновое обновление ЛКС после перезагрузки |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SPECIAL_USE` | Уведомление с текущей парой (`LessonLiveService`) |
| `REQUEST_INSTALL_PACKAGES` | Установка скачанного обновления. Android всё равно спрашивает пользователя |
| `com.rassvet.lecturial2.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | Добавляет библиотека AndroidX Core в итоговый манифест для своих внутренних приёмников, пользователю не показывается |

Доступа к контактам, местоположению, камере, микрофону, файлам пользователя
и списку приложений нет.

## Экспортируемые компоненты

| Компонент | Почему экспортирован | Чем ограничен |
| --- | --- | --- |
| `MainActivity` | Иконка в лаунчере | Intent-filter только `MAIN`/`LAUNCHER`. Явный intent может лишь открыть экран внутри приложения (Учёба, Outlook, обновления, пара из виджета) |
| `ui.OutlookAuthActivity` | Возврат из браузера после входа в Microsoft | Схема `com.rassvet.lecturial2`, хост `oauth`; `singleTask`, `noHistory`; проверка `state` и PKCE |
| `notify.BootCompletedReceiver` | `BOOT_COMPLETED`, `MY_PACKAGE_REPLACED` | Это защищённые системные broadcast-ы, сторонние приложения не могут их отправить |
| `androidx.profileinstaller.ProfileInstallReceiver` | Добавляет библиотека AndroidX Profile Installer, установка профиля оптимизации запуска | Защищён разрешением `android.permission.DUMP`, доступным только системе и отладочной оболочке |

Перечень снят с итогового манифеста release-сборки, поэтому включает компоненты библиотек.
Все остальные компоненты (`LksRefreshReceiver`, виджет, `ScheduleWidgetService`,
`LessonLiveService`, остальные receivers, `FileProvider`, `InitializationProvider`,
`MultiInstanceInvalidationService`) имеют `exported="false"`.
`FileProvider` открывает только `cache/updates/`.

## Встроенное обновление

Подробно описано в [UPDATER.md](./UPDATER.md#проверки-и-границы-безопасности).
Коротко:

- адрес проверки жёстко привязан к `neckmnull/Lecturial-2`;
- APK берётся только из `https://github.com/neckmnull/Lecturial-2/releases/download/`;
- размер не больше 250 MiB, файл должен начинаться с ZIP-заголовка;
- перед открытием установщика приложение читает APK через `PackageManager`
  и сверяет имя пакета и сертификат подписи с установленной копией
  (`isSameAppUpdate` в [`GitHubUpdateChecker.kt`](../app/src/main/java/com/rassvet/lecturial/data/network/GitHubUpdateChecker.kt)).
  Чужой APK удаляется, установка отменяется. Ротация ключа (APK Signature Scheme v3)
  поддерживается через историю сертификатов;
- установку подтверждает пользователь в системном установщике, а Android повторно
  проверяет подпись.

Так подмена APK в релизе или аккаунте GitHub не приведёт к установке без release-ключа.

## Журналы

В logcat пишутся только сообщения об ошибках с исключениями: сбой синхронизации
календаря, обновления ЛКС, входа в Outlook, обновления виджета. Cookie, токены,

## Соответствие OWASP MASVS

| Группа | Как выполнено |
| --- | --- |
| STORAGE | Секреты и данные ЛКС зашифрованы ключами Keystore, бэкап и перенос запрещены, WebView очищается после входа |
| CRYPTO | AES-256-GCM, случайный IV на каждую запись, ключи неэкспортируемые в Keystore. Своей криптографии нет |
| AUTH | Пароль ЛКС не попадает в приложение. Outlook: OAuth 2.0 + PKCE + `state` в системном браузере, секрета клиента нет |
| NETWORK | Только HTTPS, только системные CA, cookie привязаны к хосту. Pinning не используется (см. риски) |
| PLATFORM | Минимум экспортируемых компонентов, `FileProvider` только на чтение, WebView без JS-мостов и доступа к файлам, `FLAG_SECURE` и защита от оверлеев на экране входа, приватные уведомления |
| CODE | Release собирается R8, обновления проверяются по подписи, дистрибутив Gradle по SHA-256 |
| RESILIENCE | Обнаружения root и защиты от отладки нет: это не защищает данные пользователя, но мешает ему |
| PRIVACY | Нет аналитики и рекламы, данные уходят только туда, куда их отправляет сам пользователь. Экран «Конфиденциальность» в приложении это описывает |

## Остаточные риски

| # | Риск | Последствие | Почему принят |
| --- | --- | --- | --- |
| 1 | Ключи Keystore без привязки к аутентификации пользователя | Код с правами приложения (root) расшифрует сессию и оценки | Привязка остановила бы фоновое обновление и уведомления об оценках |
| 2 | Нет certificate pinning | Атака с поддельным сертификатом от доверенного системного CA | Сайты университета сами не контролируются, а Let's Encrypt, которым они пользуются, сейчас меняет цепочку (корень YR). Закреплённый сертификат сломал бы вход у всех пользователей до обновления. Для API, сертификатом которого управляет университет, pinning можно включить |
| 3 | Расписание, планы и настройки не шифруются отдельно | При доступе к файлам приложения (root, криминалистика) они читаемы | Расписание публично, планы пользователь вводит сам. Защищены песочницей и запретом бэкапа |
| 4 | Синхронизация с календарями | Пары и планы уходят в Google и Microsoft | Включается только пользователем и только в выбранный календарь |
| 5 | Refresh-токен Microsoft не отзывается при выходе | Токен действует до истечения или ручного отзыва | У Microsoft нет отзыва одного токена публичного клиента. Пользователь может отозвать доступ в учётной записи Microsoft |
| 6 | Разбор HTML ЛКС и расписания | При изменении сайта данные могут отображаться неверно | Тесты разбора, ошибки показываются пользователю, есть обязательные обновления |
| 7 | Приложение неофициальное | Университет не контролирует код и релизы. При взломе аккаунта GitHub без ключа подписи чужой APK не установится, но релиз с `lecturial-min-version` заблокирует старые версии экраном обновления, пока релиз не исправят | Код открыт, релизы подписаны одним ключом, хеш публикуется |
| 8 | Нет блокировки самого приложения (PIN, биометрия) | На разблокированном телефоне оценки и планы видны тому, кто его держит | Защита опирается на блокировку экрана; отдельный PIN мешал бы быстро смотреть расписание |
| 9 | Службы специальных возможностей могут читать экран | Вредоносная служба, которой пользователь выдал разрешение, прочитает вводимый пароль и оценки. `FLAG_SECURE` от этого не защищает | Разрешение выдаёт сам пользователь, приложение не может отличить такую службу от настоящего средства доступности |

## Если университет выдаст API

Приложение готово перейти с разбора страниц на официальный API. Предлагаемая схема:

- вход по OAuth 2.0 Authorization Code + PKCE через системный браузер, как уже сделано
  для Outlook. Пароль студента приложение не видит, секрет клиента в APK не нужен;
- узкие scope только на чтение: расписание, оценки, посещаемость, домашние задания;
- access- и refresh-токены хранятся под ключом Keystore, как токены Microsoft;
- certificate pinning для хоста API с запасным ключом, раз университет управляет
  его сертификатом;
- отзыв токена при выходе, если API это поддерживает.

## Как проверить самостоятельно

Подпись и хеш скачанного APK:

```bash
apksigner verify --print-certs Lecturial-2-v1.13.6.apk
sha256sum Lecturial-2-v1.13.6.apk
```

Разрешения:

```bash
aapt2 dump permissions Lecturial-2-v1.13.6.apk
```

Манифест целиком, с флагами `exported`:

```bash
aapt2 dump xmltree --file AndroidManifest.xml Lecturial-2-v1.13.6.apk
```

Сетевой трафик можно смотреть через прокси с пользовательским сертификатом только
на debug-сборке: release такие сертификаты не принимает.

## Как сообщить об уязвимости

Не публикуйте подробности в открытом Issue. Закрытые отчёты на GitHub
(Security → Report a vulnerability) пока не включены, поэтому откройте
[Issue](https://github.com/neckmnull/Lecturial-2/issues) с коротким описанием без
технических деталей и попросите закрытый канал связи.
