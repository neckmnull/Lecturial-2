# Участие в Lecturial 2

Прочитайте [README](README.md), [архитектуру](docs/ARCHITECTURE.md) и [правила интерфейса](DESIGN.md). Крупное изменение сначала обсудите в Issue.

## Pull Request

1. Создайте отдельную ветку с понятным названием.
2. Ограничьте изменение одной задачей, сохраните принятый стиль Kotlin.
3. Опишите проблему, новое поведение и способ проверки. Для UI приложите скриншоты без личных данных.
4. Выполните относящиеся к изменению проверки и укажите результат. Если не проверяли, напишите это явно.
5. Обновите документацию при изменении структуры, сборки или поведения.

Не добавляйте ключи подписи, пароли, токены, `local.properties`, реальные cookies/CSRF и пользовательские базы. Для сетевых примеров используйте искусственные значения.

Debug устанавливается отдельно от release. Не удаляйте release-приложение ради debug-проверки.
